# ir_rgb_gray

Classifies an image as one of four types: **rgb**, **grayscale**, **ir_whitehot**, or **ir_blackhot**.

Built for messy, low-resolution/low-quality real-world images where a single fixed rule doesn't hold up — see [Design notes](#design-notes) for why.

## Results

Cross-validated on 52 real (non-synthetic) labeled images, grouped by source so augmented copies of the same image never leak across train/test folds:

| Condition | Accuracy |
|---|---|
| Clean images | 87% |
| Simulated low-quality (downscale + noise + heavy JPEG) | 84% |

The weak spot is `grayscale` (f1 ≈ 0.55) — it has the fewest real examples (6) of the four classes. See [Known limitations](#known-limitations). Accuracy is lower than earlier internal testing because most of a real FLIR-ADAS-style dataset (34 of 37 `ir_whitehot` samples from it) was deliberately trimmed to 3 files before making this repo public — see [Data sources](#data-sources).

## Setup

```bash
python setup.py                    # interactive: choose venv or conda
python setup.py --env venv         # creates ./.venv, pip installs requirements.txt
python setup.py --env conda        # creates/reuses a conda env named ir_rgb_gray, then pip installs into it
```

Then activate it:
```bash
# venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # macOS/Linux

# conda
conda activate ir_rgb_gray
```

`tools/label_tool.py` uses `tkinter` (standard library) for its viewer — included by default on Windows/macOS Python and most conda distributions; on minimal Linux installs you may need `apt install python3-tk` first.

## Usage

### Classify a single image

```python
from ir_rgb_gray import classify_image

result = classify_image("path/to/image.jpg")
print(result.label)        # "rgb" | "grayscale" | "ir_whitehot" | "ir_blackhot"
print(result.confidence)   # 0.0-1.0
print(result.stage)        # "deterministic-channel-check" | "trained-model" | "heuristic-fallback"
```

`result.details` carries every intermediate feature value (channel stats, histogram/texture/frequency features) if you want to inspect why a decision was made.

### Classify a folder

```python
import glob
from ir_rgb_gray import classify_image

for path in glob.glob("some_folder/*.jpg"):
    r = classify_image(path)
    print(f"{path}: {r.label} ({r.confidence:.2f})")
```

### If you only care about "is it IR" (not which palette)

Training on 4 separate classes and merging `ir_whitehot`/`ir_blackhot` afterward scores *better* than training on a merged 3-class target directly (95%/90% vs. 97%/91% clean, but the merged-training model's `grayscale` recall collapses under low-quality conditions). So keep the model as-is and merge in your own code:

```python
result = classify_image(path)
is_ir = result.label in ("ir_whitehot", "ir_blackhot")
```

## Adding data

Everything flows through `data/manifest.csv` — a two-column CSV (`path,label`) that `tools/train.py` reads. Valid labels are exactly `rgb`, `grayscale`, `ir_whitehot`, `ir_blackhot`. There are three ways to add to it, depending on your starting point.

### 1. Hand-labeling a pile of unsorted images

```bash
python tools/label_tool.py path/to/unlabeled_folder
```
- Opens a small Tkinter viewer, one image at a time.
- Keys: `r`=rgb, `g`=grayscale, `w`=ir_whitehot, `b`=ir_blackhot, `s`=skip, `q`=quit.
- Each label is appended to `data/manifest.csv` immediately (as an absolute path) — safe to quit partway and resume later, since already-labeled paths are skipped automatically on the next run.

### 2. Dropping pre-sorted images into the class folders

If you already know the labels (e.g. importing another dataset), place the files under `data/samples/<class>/` — the four folders are `data/samples/rgb/`, `grayscale/`, `ir_whitehot/`, `ir_blackhot/` — then rebuild the manifest from all four at once:
```bash
python tools/manifest_from_folders.py
```
This **rewrites `data/manifest.csv` from scratch** based on whatever's currently in `data/samples/*/`, so it's for bulk-adding a folder of already-labeled images, not a one-off addition to an existing hand-labeled set (use the label tool for that, or option 3 below).

### 3. Editing manifest.csv by hand

It's a plain CSV with a header row:
```
path,label
data/samples/rgb/my_photo.jpg,rgb
data/samples/ir_whitehot/my_thermal_frame.png,ir_whitehot
```
Paths can be relative to the project root or absolute. Handy for one-off additions or appending rows generated by some other script — just don't also run `manifest_from_folders.py` afterward, since that overwrites the file.

### If your IR images are in a false-color palette, not grayscale

If the source photos use a false-color palette (e.g. FLIR's default "Ironbow": purple→orange→yellow) rather than the grayscale whitehot/blackhot this project targets, don't label them as-is. Drop them in `data/samples/ir/` and run:
```bash
python tools/derive_ir_palette_samples.py
```
It converts them to grayscale luminance (a reasonable whitehot stand-in) and inverts a subset for blackhot, writing the results into `data/samples/ir_whitehot/` and `data/samples/ir_blackhot/` — then run `manifest_from_folders.py` to pick them up.

### After adding data, retrain

New rows in `manifest.csv` don't do anything until you retrain:
```bash
python tools/train.py --augment
```
Cross-validated metrics print every run, so you'll see immediately whether the new examples helped — keep an eye on the `grayscale` class especially, since it's the one most starved for data (see [Known limitations](#known-limitations)).

## Training

```bash
python tools/train.py                 # train on data/manifest.csv as-is
python tools/train.py --augment       # also train on mild/heavy degraded copies of each image
```

This retrains the stage-B model (`grayscale` / `ir_whitehot` / `ir_blackhot`) — a `RandomForestClassifier` over 24 handcrafted features (histogram shape, Otsu blob-compactness, GLCM texture, FFT power-spectrum shape, BRISQUE-style MSCN local-contrast stats) — reports 5-fold cross-validated metrics, and saves `models/monochrome_clf.joblib`. `--augment` uses `StratifiedGroupKFold` so augmented copies of a source image can't leak across folds.

It also prints the observed `mean_channel_diff` distribution for `rgb` vs. everything else, in case `COLOR_CHANNEL_DIFF_THRESHOLD` in `ir_rgb_gray/classify.py` needs retuning for your data.

### Checking robustness to low-quality images

```bash
python tools/eval_quality_robustness.py
```
Degrades each labeled image (downscale/upscale, sensor noise, heavy JPEG re-encode) at two severities, classifies both the original and degraded versions, and reports the accuracy delta plus which classes get confused. Writes the degraded copies to `data/samples_degraded/` so you can look at them.

### Deriving whitehot/blackhot samples from false-color thermal photos

Some real thermal photos (e.g. FLIR's default "Ironbow" palette) aren't in the grayscale palette this project targets. `tools/derive_ir_palette_samples.py` converts photos in `data/samples/ir/` to grayscale luminance (a reasonable whitehot stand-in, since Ironbow brightness increases roughly monotonically with temperature) and inverts a subset for blackhot. Re-run it any time you drop more source photos into `data/samples/ir/` or `data/samples/rgb/`.


## Design notes

Two stages, because they're different kinds of problems:

1. **rgb vs. monochrome** — deterministic: compares R/G/B channels directly. An image is only `rgb` if it's stored with ≥3 channels *and* they actually diverge; a 3-channel file with R≈G≈B is treated as monochrome. Reliable enough that it needs no model.
2. **grayscale vs. ir_whitehot vs. ir_blackhot** — this is the hard part, and a hand-written rule doesn't generalize. An early version of this classifier used a fixed threshold on Laplacian variance and edge density (intuition: "thermal looks smoother") and scored **0%** on real thermal photos. Looking at what a trained model actually relies on, `mean_intensity`, `kurtosis`, and Otsu blob-compactness dominate — the two features the manual rule was built on ranked lowest. A shallow decision tree fit to the real feature distributions came within a few points of the RandomForest, confirming the *features* are enough for a classic-CV rule-based approach — it's the specific thresholds that can't be guessed by eye and need to come from labeled data.

## Known limitations

- **`grayscale` is data-starved**: only 6 real examples vs. 40 for IR combined. Precision/recall for this class should be treated as unreliable until more are labeled.
- **No genuine blackhot camera captures**: all `ir_blackhot` examples are inverted whitehot images (real thermal content, but not an authentic blackhot-palette capture). If your real data includes true blackhot output, the model has never seen one.
- **Some whitehot samples are approximated**: 10 of the whitehot/blackhot examples were derived from FLIR's false-color "Ironbow" palette via grayscale conversion (see `derive_ir_palette_samples.py`), not native grayscale-palette thermal output.

## Data sources

- Several RGB/grayscale/thermal photos are from **Wikimedia Commons**, under their respective open licenses (mostly CC-BY/CC-BY-SA) — see file names for hints, original pages searchable by title.
- Thermal pedestrian images (`otcbvs_*` files) are from the **OTCBVS OSU Thermal Pedestrian Database** (Oklahoma State University), a benchmark provided for research/educational use; please acknowledge OTCBVS if you publish anything built on this data.
- 3 `flir_real_*` files are sampled from a private FLIR-ADAS-style dataset supplied by the project owner, whose redistribution terms were never fully confirmed. The original batch (37 frames across 17 sequences) was deliberately trimmed to these 3 before this repo was made public. If you're extending this project with your own FLIR-ADAS-style data, don't assume the same is safe to publish without checking your dataset's actual license first.
